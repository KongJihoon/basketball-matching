# ADR: 신고 승인과 블랙리스트 제재 분리

## 문제 상황

신고가 접수됐다는 사실만으로 사용자를 자동 제재하면 악의적이거나 사실과 다른 신고가 즉시 서비스 이용 제한으로 이어질 수 있다. 반대로 승인과 제재를 완전히 같은 처리로 묶으면 관리자가 신고 사실은 인정하되 제재의 종류와 기간을 별도로 판단하기 어렵다.

## 선택지

### 신고 접수 즉시 자동 제재

- 구현이 단순하고 대응이 빠르다.
- 오탐과 악성 신고의 피해가 크다.
- 신고 수가 곧 유죄 판단이 되는 문제가 있다.

### 신고 승인 시 고정 제재 자동 생성

- 관리자의 사실 확인 단계가 존재한다.
- 승인과 제재가 여전히 강하게 결합된다.
- 동일한 승인이라도 상황에 따른 운영 판단을 반영하기 어렵다.

### 신고 검토와 제재 생성을 별도 기능으로 분리

- `PENDING → APPROVED/REJECTED`는 신고 판단만 표현한다.
- 승인된 신고를 근거로 관리자가 별도로 제재를 생성한다.
- 단계가 하나 늘지만 각 행위의 책임과 감사 기록이 명확하다.

## 결정

신고 검토와 블랙리스트 제재 생성을 분리한다.

- 신고 접수 시 상태는 `PENDING`이다.
- 관리자는 신고를 `APPROVED` 또는 `REJECTED`로 검토한다.
- `APPROVED` 신고만 블랙리스트의 근거가 될 수 있다.
- 승인 건수만으로 자동 제재하지 않는다.
- 신고 한 건은 하나의 블랙리스트에만 사용한다.

## 결과

신고 데이터는 사건 기록, 승인 상태는 관리자 판단, 블랙리스트는 이용 제한이라는 서로 다른 의미를 유지한다. 운영 단계가 늘어났지만 오탐 제재 위험을 줄이고 향후 기간별 제재나 다른 제재 유형을 추가할 수 있는 구조가 되었다.
