# ADR: 블랙리스트 핵심 처리와 후속 작업의 트랜잭션 분리

## 문제 상황

블랙리스트 생성은 대상 사용자의 예정 경기와 참가 관계를 정리해야 한다. 동시에 Refresh Token 삭제와 여러 사용자 알림도 필요하다. 모든 작업을 한 트랜잭션에서 수행하면 알림이나 토큰 저장소 장애가 핵심 제재와 경기 정리까지 롤백시킬 수 있다.

## 선택지

### 모든 작업을 하나의 트랜잭션에서 처리

- 한 메서드에서 전체 흐름을 확인하기 쉽다.
- 외부 저장소나 알림 실패가 DB 정합성 작업을 방해한다.
- 트랜잭션이 길어지고 책임이 과도하게 커진다.

### 모든 작업을 비동기 처리

- 관리자 요청 응답이 빠르다.
- 제재와 경기 정리 사이에 일시적인 불일치가 발생한다.
- 실패 복구 장치가 없으면 핵심 정합성도 보장할 수 없다.

### 핵심 정합성은 같은 트랜잭션, 부수 효과는 커밋 이후 처리

- 블랙리스트 저장과 경기 정리는 원자적으로 처리된다.
- 토큰 삭제와 알림은 확정된 데이터에 대해서만 실행된다.
- 후속 이벤트 유실에 대한 별도 대책이 필요하다.

## 결정

`BlackListService` 트랜잭션 안에서 블랙리스트 저장과 `BlackListGameService.cleanup()`을 수행한다. cleanup에는 `MANDATORY` 전파 옵션을 적용해 독립 호출을 막는다.

Refresh Token 삭제와 알림은 `UserBlacklistedEvent`를 발행한 뒤 `AFTER_COMMIT`, `REQUIRES_NEW` 리스너에서 처리한다.

## 결과

제재와 경기 상태의 정합성을 유지하면서 알림 장애로 핵심 작업이 취소되는 문제를 피했다. 다만 현재 이벤트는 프로세스 메모리에 의존하므로 커밋 직후 서버가 종료되면 후속 작업이 유실될 수 있다. 전달 보장이 중요해지면 Transactional Outbox와 재시도 정책을 추가한다.
