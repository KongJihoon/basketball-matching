# ADR: 영속 알림과 실시간 전용 알림의 분리

## 문제 상황

모든 알림을 DB에 저장하면 조회와 관리 비용이 증가한다. 반대로 모든 알림을 SSE와 Redis Pub/Sub으로만 전달하면 연결이 끊긴 사용자는 중요한 알림을 다시 확인할 수 없다. 다중 서버 환경에서는 각 서버 메모리에 보관된 `SseEmitter`에도 이벤트를 전달해야 한다.

## 선택지

### 모든 알림을 DB에 저장하고 polling

- 전달 이력과 재조회가 쉽다.
- 즉시성이 떨어지고 반복 조회 부하가 발생한다.

### 모든 알림을 SSE와 Redis Pub/Sub으로만 전달

- 실시간 전달 구조가 단순하다.
- 연결이 없는 동안의 이벤트와 서버 장애 시 메시지가 유실된다.

### 중요도에 따라 영속 알림과 실시간 전용 알림을 구분

- 중요 알림은 DB에서 재조회할 수 있다.
- 실시간 편의 알림은 낮은 비용으로 전파할 수 있다.
- 이벤트별 전달 보장 정책을 명확히 관리해야 한다.

## 결정

경기 수정·삭제·강퇴·블랙리스트 등 사후 확인이 필요한 알림은 DB에 저장한 뒤 SSE로 전송한다. 경기 생성 알림은 실시간 편의 정보로 보고 Redis `game.created` Pub/Sub과 SSE로만 전달한다.

각 인스턴스는 로컬 emitter를 관리하며 Redis 구독을 통해 동일 메시지를 수신한다. 재연결용 로컬 이벤트 캐시는 5분 TTL로 제한한다.

## 결과

알림 중요도에 맞춰 저장 비용과 전달 보장을 선택할 수 있게 됐다. Redis Pub/Sub은 다중 인스턴스 실시간 전파를 해결하지만 영속성과 재전송을 보장하지 않는다. 경기 생성 알림의 요구사항이 바뀌면 DB 저장, Redis Streams 또는 메시지 브로커로 전환해야 한다.
