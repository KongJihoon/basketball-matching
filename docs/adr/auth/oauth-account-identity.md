# OAUth 계정을 Provider 고유 ID로 식별

## 문제 상황

기존 카카오 로그인은 이메일을 사용하여 사용자를 식별하였다.

하지만 이메일은 변경되거나 제공 동의가 철회될 수 있고,
다른 로그인 제공자 또는 LOCAL 계정과 카카오 계정을 자동 연결하면

실제 계정 소유권 확인 없이 인증 수단이 추가되어 계정 탈취 위험이 존재한다.

---

## 선택지

### 선택지 1. 이메일을 OAuth 계정 식별자로 유지

#### 장점

- 별도 OAuth 계정 테이블이 필요하지 않다.
- 사용자 조회 로직이 단순하다.

#### 단점

- 이메일 변경과 제공 동의 철회에 취약하다.
- 다른 로그인 제공자 확장이 어렵다.
- LOCAL 계정과의 안전한 연결 정책을 구현하기 어렵다.

### 선택지 2. Provider와 Provider User ID 사용

#### 장점

- 이메일 변경과 무관하게 소셜 계정을 식별할 수 있다.
- 여러 OAuth Provider로 확장할 수 있다.
- 사용자와 인증 제공자 계정의 관계를 명시적으로 관리할 수 있다.
- DB 유일 제약조건으로 중복 연결을 방지할 수 있다.

#### 단점

- OAuthAccountEntity와 Repository가 추가된다.
- 기존 사용자와 OAuth 계정의 연결 정책이 필요하다.

---


## 결정

OAuth 계정은 다음 조합으로 식별한다.

```text
OAuthProvider + providerUserId
```

카카오는 카카오 사용자 정보 API의 고유 ID를 `providerUserId`로 사용한다.
사용자와 OAuth 계정의 관계는 OAuthAccountEntity에 저장한다.

---

## 결과

- 이메일 변경과 무관한 OAuth 계정 식별
- 동일 카카오 계정의 중복 가입 방지
- 한 사용자에게 동일 Provider가 중복 연결되는 상황 방지
- LOCAL 계정 자동 연결로 인한 계정 탈취 위험 감소
- 다른 OAuth Provider 확장을 위한 기반 마련
